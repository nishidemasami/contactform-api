# LLM-WIKI 運用ルール

本ドキュメントは、[LLM-WIKI](https://gist.githubusercontent.com/karpathy/442a6bf555914893e9891c11519de94f/raw/ac46de1ad27f92b28ac95459c782c07f6b8c964a/llm-wiki.md) の考え方に基づき、`contactform-api` リポジトリにおいてAIエージェントがウィキを運用するためのルールを定めたものである。

---

## 1. ウィキの目的と位置づけ

本ウィキは、`docs/raw/*.md` に投入された生情報（規約・要件・議事録・メモ等）をもとに、AIエージェントが整理・統合・維持管理する **永続的な知識ベース** である。

- **人間** は `docs/raw/` に情報を投入し、ウィキの内容をレビュー・承認する。
- **AIエージェント** は `docs/wiki/` を読み書きし、常に最新・整合性のとれた状態を維持する。
- RAGのように毎回ゼロから情報を探すのではなく、ウィキ自体がすでに統合・整理された状態であることを目指す。

---

## 2. ディレクトリ構成とファイルの役割

```
docs/
  raw/          生情報の格納ディレクトリ（人間が投入、AIは読み取り専用）
  wiki/         ウィキ本体（AIが書き込み・更新）
    llm-wiki.md       このファイル。ウィキ運用ルールそのもの（=スキーマ定義）
    index.md          ウィキ全ページの目次・一覧（AIがingest毎に更新）
    log.md            操作ログ（append-only、ingest/query/lintの記録）
    overview.md       プロジェクト全体概要・アーキテクチャサマリ
    requirements.md   要件定義まとめ
    coding-conventions.md   コーディング規約（Rust/アーキテクチャ/DDD）
    api.md            API規約・Lambda最適化設計
    infrastructure.md AWS SAM・インフラ構成規約
    database.md       DB規約（Liquibase・Aurora DSQL・SeaORM）
    frontend.md       フロントエンド規約（Next.js/TypeScript/Tailwind CSS）
    cicd.md           CI/CD規約（GitHub Actions）
    review-process.md レビュープロセス・PR運用規約
    github-settings.md  GitHubリポジトリ設定・構成
    aws-settings.md   AWS設定・SSMパラメータ体系
    known-issues.md   既知の問題・バックログ
    backlog.md        バックログ・懸念事項・TODO
```

### ファイル分類

| ファイル | 種別 | 説明 |
|---|---|---|
| `llm-wiki.md` | スキーマ | ウィキ運用ルール（本ファイル） |
| `index.md` | ナビゲーション | 全ページ目次 |
| `log.md` | ログ | append-only 操作記録 |
| その他 | コンテンツ | 実際の知識ページ |

## 3. レイヤー構成

本ウィキは以下の3レイヤーで構成される。

### レイヤー1: 生情報（Raw Sources）
- **場所**: `docs/raw/*.md`
- **管理者**: 人間
- **方針**: イミュータブル。AIは読み取りのみ行い、絶対に編集・削除しない。
- **内容**: 規約原文、要件定義、設計方針、議事録、メモ、外部資料など。

### レイヤー2: ウィキ（Wiki）
- **場所**: `docs/wiki/*.md`
- **管理者**: AIエージェント
- **方針**: AIが作成・更新・整合性維持を担う。人間はレビューのみ行う。
- **内容**: 要約、エンティティページ、概念ページ、比較表、全体概要、統合的知識。

### レイヤー3: スキーマ（Schema）
- **場所**: `docs/wiki/llm-wiki.md`（本ファイル） および `AGENTS.md`
- **管理者**: 人間とAIが協調して育てる
- **内容**: ウィキの構造・規約・AIの振る舞いを定義する。

## 4. 基本操作（Operations）

### 4.1. Ingest（情報取り込み）

人間が `docs/raw/` に新しいファイルを追加した場合、またはAIが変更を検知した場合に実施する。

**手順**:
1. 対象の `docs/raw/*.md` を精読する。
2. 重要な情報・変更点を把握し、既存ウィキとの差分を確認する。
3. 影響する `docs/wiki/*.md` を特定し、以下を実施する。
   - 新規情報を追加する。
   - 既存の内容を更新・修正する。
   - 矛盾がある場合は明記し、解決方針を記載する。
4. `docs/wiki/index.md` を更新する。
5. `docs/wiki/log.md` にingestエントリを追加する。

**記録フォーマット（log.md）**:
```
## [YYYY-MM-DD] ingest | ファイル名
- 更新したウィキページ: xxx.md, yyy.md
- 概要: 変更内容を簡潔に記述
```

### 4.2. Query（質問応答）

ウィキに対して質問が来た場合の手順。

**手順**:
1. `docs/wiki/index.md` を参照して関連ページを特定する。
2. 関連ページを精読し、回答を合成する。
3. 回答は出典（参照したwikiページ）を明記する。
4. 価値ある回答・分析・発見は `docs/wiki/` に新規ページとして保存する。
5. `docs/wiki/log.md` にqueryエントリを追加する。

**記録フォーマット（log.md）**:
```
## [YYYY-MM-DD] query | 質問タイトル
- 参照ページ: xxx.md, yyy.md
- 概要: 質問の概要と得られた知見
```

### 4.3. Lint（健全性チェック）

ウィキの健全性を定期的にチェックし、以下を確認・修正する。

**チェック項目**:
- ページ間の矛盾・不整合
- 古くなった情報（新しい `docs/raw/` に上書きされた内容）
- 孤立ページ（どこからもリンクされていないページ）
- 重要な概念が存在するのにページがない箇所
- クロスリファレンスの欠落
- `index.md` に掲載されていないページ

**手順**:
1. 全ウィキページを横断的に確認する。
2. 発見した問題を修正する。
3. 補完が必要な情報はWebサーチや `docs/raw/` を参照する。
4. `docs/wiki/log.md` にlintエントリを追加する。

**記録フォーマット（log.md）**:
```
## [YYYY-MM-DD] lint | ヘルスチェック
- 修正したページ: xxx.md, yyy.md
- 発見した問題: 矛盾箇所、孤立ページ等
- 概要: 実施内容の要約
```

## 5. ページ記述ルール

### 5.1. 共通フォーマット

各ウィキページは以下のフォーマットを基本とする。

```markdown
# ページタイトル

> 最終更新: YYYY-MM-DD | ソース: raw/ファイル名.md

このページの一文概要。

---

## セクション1

内容...

## 関連ページ

- [ページ名](./ページファイル名.md)
```

### 5.2. クロスリファレンス

- 他のウィキページへの参照は相対パス `./ページ名.md` で記述する。
- 生情報への参照は `../raw/ファイル名.md` で記述する（読み取り専用の旨を明記）。
- 関連ページへのリンクは各ページ末尾の「関連ページ」セクションにまとめる。

### 5.3. 矛盾・不確かな情報の扱い

- ページ間で矛盾が見つかった場合は、該当箇所に以下のマーカーを付ける。
  ```
  > ⚠️ 矛盾あり: [矛盾するページ](./矛盾ページ.md) と内容が異なります。要確認。
  ```
- 情報が古い可能性がある場合は以下を付ける。
  ```
  > ℹ️ 要確認: この情報は最新でない可能性があります。
  ```

## 6. ページ更新ルール

### 6.1. 更新時の注意

- 1つの `docs/raw/*.md` の取り込みで複数のウィキページが更新されることがある（10〜15ページ程度）。
- 更新するたびに `index.md` と `log.md` も必ず更新する。
- ウィキページを削除する場合は、`log.md` に削除の記録を残す。

### 6.2. `index.md` のフォーマット

```markdown
# ウィキ インデックス

> 最終更新: YYYY-MM-DD

| ページ | 概要 | 最終更新 |
|---|---|---|
| [overview.md](./overview.md) | プロジェクト全体概要 | YYYY-MM-DD |
| ... | ... | ... |
```

### 6.3. `log.md` のフォーマット

- append-only（既存エントリは絶対に編集・削除しない）。
- エントリの冒頭は `## [YYYY-MM-DD] <操作種別> | <タイトル>` で始める。
- これにより `grep "^## \[" log.md` でエントリ一覧を取得できる。

## 7. AIエージェントへの指示

本ウィキを運用するAIエージェントは以下を遵守すること。

1. **`docs/raw/` は読み取り専用**。絶対に編集・削除しない。
2. **`docs/wiki/` のみ書き込む**。`docs/raw/` や他のディレクトリには書き込まない。
3. **Ingest前に `index.md` を確認**し、既存ページの全体像を把握してから更新を行う。
4. **毎回 `log.md` を更新**する（操作の記録は必須）。
5. **矛盾を放置しない**。矛盾を発見したら必ずマーカーを付けるか解消する。
6. **コンテキストを引き継ぐ**。セッション開始時は `index.md` と `log.md` の末尾を読み、直前の状態を把握してから作業する。
7. **プルリクエストを作成する**。ウィキ更新はプルリクエスト経由でマージされる。人間によるレビューを受けること。
8. **`llm-wiki.md` 自体を更新できる**。運用の中で改善点が見つかれば、このファイルを更新し、ルールを育てていく。

## 8. 開発フローにおけるウィキの役割

本プロジェクトの開発フローとウィキの関係は以下の通りである。

```
[人間] docs/raw/*.md に規約・要件・議事録等を投入
         ↓
[AI] docs/wiki/*.md へ情報を整理・統合（ingest）→ プルリクエスト作成
         ↓
[人間] レビュー・承認・マージ
         ↓
[AI] docs/wiki/*.md に従い実装
         ↓
[CI/CD] テスト・カバレッジレポート・レビュー資料の生成・デプロイ
         ↓
[人間] 実装・レビュー資料・カバレッジレポートをレビュー → 承認・マージ
         ↓
[CI/CD] テスト環境へデプロイ
         ↓
[人間] 手動テスト → 本番環境へデプロイ
```

ウィキは「AIが実装の根拠とする唯一の仕様書」として機能する。
生情報（`docs/raw/`）をそのまま参照するのではなく、整理・統合されたウィキページを参照して実装することで、情報の散逸を防ぎ実装品質を高める。
