# 00000008_AWS規約と実装例

## Github-AWS間OIDC設定

### 事前準備

- プロジェクトの`service_name`を決定する
- `AWS_ACCOUNT_ID`を確認する
  AWSマネジメントコンソールの右上に書いている
- OIDCのsubクレームプレフィックス欄を確認する
  GitHubリポジトリのSettings > Actions > OIDC > `Default subject claim prefix`欄
- SAMテンプレート配置用S3バケットを作成する

### CloudFormation用IAMロール

ポリシーは必要最小限だけ設定する。  
方法としては、個別環境でデプロイを実施し、AWS CloudTrailのログをIAM Access Analyzerに読み込ませて必要な権限を得る、などの手法を用いる。  
リソース名を指定した条件指定(Resourceを`/<service_name>-*`にするなど)、Tagを指定した条件指定(Createを`aws:RequestTag`、EditやDeleteを`aws:ResourceTag`、AddTagsやRemoveTagsではその両方を指定する)等を活用する。  
TagのEnvironmentが`Release`の場合はDelete権限を与えない、なども有効。  
非常に複雑で難しいがセキュリティ上重要なので、専門知識を持った人の助力を得ながら実施する。

### ログイン用ポリシー

GitHub Actionsからのログイン要求（OIDC）を信頼するための設定。

#### 信頼関係 > 信頼されたエンティティ
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Federated": "arn:aws:iam::<AWS_ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com"
            },
            "Action": "sts:AssumeRoleWithWebIdentity",
            "Condition": {
                "StringEquals": {
                    "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
                    "token.actions.githubusercontent.com:sub": [
                      "repo:<OIDCのsubクレームプレフィックス>:ref:refs/heads/develop",
                      "repo:<OIDCのsubクレームプレフィックス>:ref:refs/heads/release",
                      "repo:<OIDCのsubクレームプレフィックス>:pull_request"
                    ]
                }
            }
        }
    ]
}
```

#### 許可 > 許可ポリシー
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "CloudFormationDeployTrigger",
            "Effect": "Allow",
            "Action": [
                "cloudformation:CreateChangeSet",
                "cloudformation:ExecuteChangeSet",
                "cloudformation:DescribeStacks",
                "cloudformation:DescribeStackEvents",
                "cloudformation:DescribeChangeSet",
                "cloudformation:GetTemplateSummary"
            ],
            "Resource": "arn:aws:cloudformation:*:<AWS_ACCOUNT_ID>:stack/<service_name>-*"
        },
        {
            "Sid": "S3BucketListAccess",
            "Effect": "Allow",
            "Action": "s3:ListBucket",
            "Resource": "arn:aws:s3:::<SAM配置用S3バケット>"
        },
        {
            "Sid": "S3ObjectReadWriteAccess",
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::<SAM配置用S3バケット>/*"
        },
        {
            "Sid": "PassRoleToCloudFormation",
            "Effect": "Allow",
            "Action": "iam:PassRole",
            "Resource": "<CloudFormation用IAMロールのARN>",
            "Condition": {
                "StringEquals": {
                    "iam:PassedToService": "cloudformation.amazonaws.com"
                }
            }
        },
        {
            "Sid": "AllowCreateSLRForDSQL",
            "Effect": "Allow",
            "Action": "iam:CreateServiceLinkedRole",
            "Resource": "arn:aws:iam::*:role/aws-service-role/dsql.amazonaws.com/AWSServiceRoleForDSQL*",
            "Condition": {
                "StringEquals": {
                    "iam:AWSServiceName": "dsql.amazonaws.com"
                }
            }
        }
    ]
}
```

## GitHub Actions設定

GitHubリポジトリのSettingsから、`Environment secrets`として以上で設定したARNを指定する。

GitHub Actionsでは以下のように利用する。

```yaml
      - name: AWSクレデンシャルの設定
        uses: aws-actions/configure-aws-credentials@v6
        with:
          role-to-assume: ${{ secrets.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ap-northeast-3
```

`Environment secrets`では、必要に応じて`Deployment protection rules`で`Required reviewers`をONにするなどして保護する。
