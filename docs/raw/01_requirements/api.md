# 問い合わせAPI 要件定義

## 概要
コンタクトフォームからのリクエストを受け付け、問い合わせデータをデータベースに安全に保存するバックエンドAPI。

## API仕様要件
- **エンドポイント**: `POST /api/v1/inquiry`
- **通信形式**: JSON (`Content-Type: application/json`)
- **入力リクエストデータ**:
  - `name`: 氏名（文字列）
  - `email`: 連絡先メールアドレス（文字列）
  - `message`: 問い合わせ本文（文字列）
- **レスポンス要件**:
  - 成功時 (`201 Created`): 生成された問い合わせID (`id: Uuid`) を返却。
  - 入力エラー (`400 Bad Request`): バリデーションエラーメッセージを返却。
  - サーバーエラー (`500 Internal Server Error`): 内部エラーメッセージを返却（インフラの内部エラー詳細は隠蔽する）。

## データベース・セキュリティ要件
- データ保存先: Amazon Aurora DSQL (`inquiries` テーブル)
- アクセス権限: 問い合わせ登録処理を実行するLambda実行ロールには、`inquiries` テーブルに対する **`INSERT` 権限のみ** を付与し、`SELECT` や `UPDATE` / `DELETE` 権限は一切与えない。
- データ整合性・セキュリティ: SQLインジェクションを防ぐため、常にプレースホルダーバインドを使用したステートメント実行を行う。
